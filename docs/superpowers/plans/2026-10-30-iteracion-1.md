# Iteración 1 (A1 u. 1 "Ankommen") — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** La app se usa a diario en el iPhone para subir la escalera de 5 escalones de 3 temas de A1 u. 1. La escritura se corrige con LanguageTool, el feedback no muestra la solución y la identidad visual es A1 "cuaderno sereno".

**Architecture:**
- El contenido se escribe en YAML (`content-src/`) y se compila a JSON commiteado (`data/`).
- La lógica pura vive en `js/core/` y se hace con TDD (`node --test`). Cada tipo de ejercicio tiene un check puro en `js/core/checks/` y su UI en `js/exercises/`.
- La UI arma un grupo (un escalón), corrige cada respuesta y guarda después de cada una en IndexedDB.

**Tech Stack:** HTML, CSS y JS con módulos ES, sin build ni dependencias en runtime. Python 3 con PyYAML para las herramientas. LanguageTool en Docker para la CI y la API pública para lo que escribe el usuario. GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-30-iteracion-1-design.md` (de acá en adelante "spec"). También rigen `docs/PLAN.md` §3 y §7; las reglas se citan como "regla N" de §7.

## Global Constraints

- Sin build en el código de la app y sin dependencias en runtime. Las herramientas declaran PyYAML en `tools/requirements.txt`.
- iOS Safari 16.4 o posterior. Node 22 en la CI. En local los tests corren con Node 18 o más nuevo.
- La UI está en español rioplatense, con voseo ("tocá", "respondé"). La terminología va en alemán con aclaración: "Akkusativ (objeto directo)".
- **Feedback de error:** nunca muestra la forma correcta de un ítem cerrado ni ofrece reintento (reglas 2 y 3). El ejemplo distinto difiere en la dimensión evaluada (regla 1).
- **Normalización:** ß, umlaut y mayúscula se exigen solo en tags ortográficos; en los demás se aceptan con aviso (regla 12). Todo `<input>` y `<textarea>` de respuesta lleva `autocapitalize="off" autocorrect="off" spellcheck="false"`.
- **Nada de control del tiempo:** sin cronómetros, metas de minutos ni contadores de racha (spec §2).
- **Umbrales:**
  - Escalones 1–4: se superan con el 80 % de los ítems del tema.
  - Escalón 5: se supera con 2 de 3 escrituras sin ningún error.
  - Tema dominado: los 5 escalones superados y el mastery mínimo de sus tags ≥ 0.8.
  - Para reforzar: algún tag del tema con datos < 0.5.
  - Gating: los `requires` tienen que tener mastery ≥ 0.6 **[decisión del plan]**.
- **Ítems por escalón** (spec §5.3):

  | Escalón | Ítems |
  |---|---|
  | 1 | 10–12 |
  | 2 | 14–18 |
  | 3 | 14–18 |
  | 4 | 12–16 |
  | 5 | 3 escrituras + 4–6 de repaso |

  En los escalones 2–4, cerca del 20 % de los ítems es de repaso y no cuenta para el porcentaje.
- **Tokens visuales** (spec §7):

  | Token | Valor |
  |---|---|
  | `--ground` | `#ffffff` |
  | `--surface` | `#f3f1ea` |
  | `--text` | `#1f201d` |
  | `--muted` | `#636361` |
  | `--accent` | `#1b6e66` |
  | `--accent-tint` | `#e3efed` |
  | `--negative` | `#b42318` sobre `#fdecea` |

  Las fuentes son Instrument Serif e Instrument Sans 400/500/600, en woff2 servidas desde la app. Las tarjetas tienen radio de 22 px, sin sombras ni gradientes, márgenes de 16 px y controles de 44 px o más.
- **Privacidad:** nada personal en el repo (regla 19). `.superpowers/`, `.taste-skill/` y `privado/` ya están en `.gitignore`.
- **LanguageTool:** la CI y las herramientas usan solo el de Docker (`LT_URL`). La API pública se usa solo desde la app, para el texto del usuario.
- **Commits:** en castellano y terminados con la línea `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Se trabaja en la rama `docs/diseno-iteracion-1` o en una rama nueva `feat/iteracion-1` que salga de ella. Nunca en `main`.

## Review Focus

1. **Cerrar la app a mitad de grupo**, incluso en la pantalla de feedback, y volver a abrirla: retoma en el ejercicio siguiente sin contar dos veces la respuesta ni perderla (Tarea 9, test `resume no duplica`).
2. **LanguageTool sin red, con 429 o con 5xx:** la escritura queda "pendiente de corrección", nunca "incorrecta". Se corrige al volver la red, aunque el grupo ya haya terminado (Tarea 7, test `fallo de red → pendiente`; Tarea 9, test `escalón 5 con pendiente`).
3. **Lo que mete el teclado del iPhone:** comillas y apóstrofos tipográficos (’ „ “), punto final, espacios dobles y mayúscula inicial en una respuesta que no es ortográfica. Se aceptan, con aviso donde corresponde (Tarea 3, test `variantes del teclado iOS`).
4. **Primer uso, sin datos:** no hay ítems de repaso, la sugerencia es tema 1 escalón 1, el saludo tiene una línea por defecto y el glosario completa con palabras nuevas (Tarea 9, test `primer uso`; Tarea 10, test `sin vistas`).
5. **`order` con chunks repetidos** (dos veces *die*): se corrige por el texto de los chunks, no por su índice, así que cualquier orden válido de los repetidos cuenta como correcto (Tarea 6, test `chunks repetidos`).

## Tarea 3: `normalize.js`

**Interfaces:**

- [ ] **Paso 1: Escribir los tests:**

```js
test('exacto', () => assert.deepEqual(matchAnswer('den', ['den'], {orthographic: false}), {ok: true, notice: null}));
test('variantes del teclado iOS', () => {
  assert.equal(matchAnswer('  Ich  bin  müde. ', ['ich bin müde'], {orthographic: false}).ok, true);
  assert.equal(matchAnswer('Wie geht’s?', ["Wie geht's?"], {orthographic: false}).ok, true);
});
test('mayúscula inicial no ortográfica: ok sin aviso', () =>
  assert.deepEqual(matchAnswer('Den', ['den'], {orthographic: false}), {ok: true, notice: null}));

  assert.deepEqual(matchAnswer('Strasse', ['Straße'], {orthographic: false}), {ok: true, notice: 'ojo: ß'}));

test('sustantivo en minúscula no ortográfico: ok con aviso', () =>
  assert.deepEqual(matchAnswer('ich brauche einen löffel', ['Ich brauche einen Löffel'], {orthographic: false}),

test('nunca borra el rasgo evaluado: einen ≠ ein', () => assert.equal(matchAnswer('ein', ['einen'], {orthographic: false}).ok, false));
```

- **Entrada del léxico:**

  ```yaml

  ```

  - `freq`: 1 = muy frecuente, 3 = poco.
  - Los verbos llevan `pos: verb` y, si hacen falta, `irregular`.
  - Son unas 150 palabras, repartidas en los campos de las escenas de la spec §6: hostel, wohnung, kueche, essen, einkaufen, personen, laender.
- **Plantilla:**

  ```yaml
  - {id: tpl-brauchen-akk, tag_prefix: a1.akk, det: indef, kase: akk, context: "En el súper, con la lista en la mano.",
     text: "Ich brauche ___ {noun}.", slot: {pos: noun, fields: [essen, kueche], countable: true}}
  ```

- Produces: `generate(template, lexicon, rng) → Exercise`. El ejercicio es de tipo `gap` (formato en la Tarea 6), con:
  - `id`: `${template.id}:${lemma}`
  - `tag`: `${tag_prefix}.${mask|fem|neut|plural}`
  - `answers`: `article(...)`
  - `dims`: `{gender}`
  - `generated: true`
- Produces: `instances(template, lexicon) → Exercise[]`, con todas las palabras que caben en la ranura (la usa `german_texts.mjs`).
- Produces: `diagnose({tag, dims: {gender, kase, det}}, answer) → {rule: string, prereq: string|null}`. El texto nombra la regla y nunca la forma esperada:

  | La respuesta coincide con… | `rule` | `prereq` |

## Tarea 14: Correr un grupo (runner, ejercicios, feedback y fin)

**Files:**
- Create:
  - `js/ui/grupo.js`
  - `js/ui/fin.js`
  - `js/ui/ficha.js` (también se usa sola)
  - `js/exercises/{choice,gap,situation,transform,translate,order,spot-error,reading,detective,writing}.js`
  - `js/exercises/index.js`
- Modify: `js/app.js` (rutas), `sw.js` (SHELL).

**Interfaces:**
- Plugin de UI: `render(exercise, el, {submit(answer), ctx}) → void`. Cada plugin dibuja sus controles y llama a `submit` una vez.
- Rutas:
  - `#/grupo/<topicId>/<n>`: arma el grupo o retoma `group` si coincide;
  - `#/fin`;
  - `#/ficha/<topicId>`.
- **Flujo del runner por ejercicio:**
  1. `render`.
  2. `submit`.
  3. `checkExercise`.
  4. Guardar `group` con los `results` y `index + 1`. Esto es el autoguardado.
  5. Mostrar el feedback.
  6. "Siguiente": `commitNext` → `applyResult` sobre cada resultado + `answerEntry` y `countWords` al log → guardar `mastery`, `log`, `words` y `progress.seen`.
- Al reabrir: si `group.index > group.committed`, primero `commitNext` y después renderiza `exercises[index]`.
- **Feedback por `Result`** (spec §5.6):
  - **Error:** etiqueta `.tag-bad` "Incorrecto", la `rule`, el ejemplo de `pickExample`, "ver ficha" y **Siguiente**. Nunca aparece la respuesta aceptada.
  - **Acierto:** "Bien", más `pickCuriosity` si devuelve algo.
  - `notice` se muestra como línea muted, por ejemplo "ojo: ß".
  - En `situation`, cada hueco fallado se pone rojo (`.gap.bad`) con su regla.
- **Botón ⚑ "Creo que esto está mal"** en la pantalla de feedback:
  - pide una nota opcional;
  - agrega `{exerciseId, answer, note, at}` a `reports`;
  - agrega el id a la cuarentena (clave `quarantine`, array) **antes** del commit, así ese resultado no toca el mastery (regla 4).
- **Escritura:**
  - Muestra consigna, tips y restricciones, `answerInput({multiline: true})` y "Enviar".
  - Si el `Result` es `pending`: "Sin conexión: la corregimos cuando vuelva la red", `enqueue` y el grupo sigue.
  - Si no: el texto con `marks` subrayadas (error en rojo, aviso en muted) y su `text` debajo; después el checklist (tildes locales) y el `model`.
  - "Reescribir" es opcional: vuelve a corregir y muestra las marcas, pero no cambia el `Result`.
  - Cada `ltRules` va al log como `ltEntry`.
- **Ficha en el escalón 1** (spec §5.3): se muestra después del primer `detective`, o antes del primer ejercicio si el tema es `arbitrary`. Si `showFicha`, aparece antes de la parte `apply`.
- **Grupo abandonado:** si se empieza un grupo distinto del guardado en `group`, el guardado va al log como `groupEntry({…, abandoned: true})`.
- **`order`:** se tocan chunks para armar la frase; tocar un chunk ya usado lo devuelve.
- **`spot-error`:** se toca una palabra y aparece un input para corregirla.
- **✕ arriba:** vuelve al inicio sin confirmar y deja `group` guardado.
- **Fin** (spec §5.7):
  - aplica `scoreGroup` y escribe el intento en `progress`;
  - `groupEntry` al log;
  - borra `group`;
  - muestra el %, "Superado" o "Para reforzar" (o "Esperando la corrección de N escrituras") y la lista de `failedRules`;
  - botones "Siguiente grupo" (`suggestNext`) e "Inicio".
- **Escalón 3:** antes del primer ejercicio muestra el glosario (Tarea 15) y deja un botón "Glosario" en la barra del grupo.
